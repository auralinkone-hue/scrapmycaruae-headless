# Staging quote submission incident — 22 October 2026

Starting commit: `aaea9b580958068cfc9915a08ec3c91a00f2ecb9`, `development` only. Target Worker: `smc-headless-worker`, https://smc-headless-worker.hussain-gscx.workers.dev/ . Investigation times below are UTC; add five hours for Asia/Karachi.

## Confirmed root cause

The deployed quote route supplied a missing build-time value (`undefined` / `void 0`) to `requireQuoteRequestsCollectionId`. The Cloudflare runtime had a `WIX_QUOTE_REQUESTS_COLLECTION_ID` secret binding, but the old route read only `import.meta.env.WIX_QUOTE_REQUESTS_COLLECTION_ID`. A runtime secret does not repair a missing value already compiled into the bundle.

This is proven by both sanitized deployed-code inspection and persisted Worker logs. Matching failures at 10:51:52.127, 10:52:10.237 and 10:52:50.817 logged `Quote submission collection configuration is unavailable.` and returned HTTP 500. The inspected failing invocations had normal Worker outcomes, 0–7ms CPU and 1–18ms wall time. They stopped before parsing customer details, Wix visitor-token generation, catalogue validation, insertion, D1 or Brevo. No resource exhaustion or Brevo/provider failure explains these matched requests.

We have not established which earlier deployment/configuration action produced the missing build value. The timing of Brevo configuration alone does not prove that Brevo caused it.

## Did the original attempt save?

No matched failed request reached insertion. A read-only, consistent CMS query returned **all 36** `QuoteRequestsStaging` rows, with newest timestamp `2026-10-22T10:28:28.054Z`; none was in the 10:48–10:58 window. Only timestamps/source were requested; customer names/phones were not returned. Wix returned timestamp wrappers; the audit normalized those returned timestamps rather than relying on string comparisons against wrapper objects.

No existing staging enquiry or D1 record was deleted or modified. No production collection was queried or written.

## Smallest corrective changes

- `src/pages/api/quote.ts`: use the Cloudflare runtime collection binding, with the existing build configuration as fallback. Log only fixed notification-gate/outcome codes on the server for safe verification. Save order and WhatsApp response remain intact.
- `src/lib/quote-collection.ts`: retain format validation and additionally prohibit staging from writing to any collection other than `QuoteRequestsStaging`. A present invalid runtime value is rejected; it does not silently fall back.
- `tests/quote-notifications.test.mjs`: execute the actual route against mocked Wix/D1/Brevo. Cover missing build value plus runtime binding, invalid/production runtime values, token/catalogue failure before insert, scheduling exception after save, and email-off behavior. Existing notification deduplication tests remain passing.
- `scripts/diagnose-development-quote.mjs` and its workflow: read-only Cloudflare settings, deployed-code booleans and bounded persisted logs. No secret values, raw log messages, headers, request bodies or customer details are emitted. No submissions or emails are generated by this diagnostic.
- Development deploy workflow: `[diagnostic-only]` commits skip deployment so evidence-gathering does not replace the incident's running code. Normal fix commits still deploy staging.

Brevo fields and the D1 binding are separate from the OAuth public client and collection setting; no credentials were copied or repurposed. Notifications still run only after a confirmed Wix insert under `waitUntil`. Off returns before hashing, D1 writes or Brevo requests. Ledger/provider/scheduler failures remain isolated from a saved enquiry, with permanent at-most-once notification claims. No retries were added.
